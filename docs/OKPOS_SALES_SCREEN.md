# OKPOS 스타일 POS 판매 화면

## 화면 흐름
1. 후불제 POS 판매 진입 시 테이블 현황 화면을 먼저 표시한다.
2. 등록된 테이블을 터치 가능한 카드형 박스로 표시한다.
3. 주문이 없는 테이블은 '주문 대기', 진행 중인 테이블은 '주문 진행중'과 주문금액/경과시간을 표시한다.
4. 테이블 박스를 누르면 해당 테이블의 판매 화면으로 전환한다.
5. 판매 화면의 '테이블 목록' 버튼으로 테이블 현황으로 돌아간다. 저장하지 않은 상품이 있으면 이동 전에 확인한다.
6. 테이블 화면의 '메뉴표기' 버튼은 진행 중인 테이블의 주문 메뉴 요약 표시를 전환한다.

## 테이블 화면에서 판매 화면으로
- 테이블 목록은 POS_TABLE의 매장별 활성 테이블을 기준으로 표시한다.
- 진행 중 주문은 POS_ORDER의 OPEN 상태와 주문금액/최초 주문시각을 사용한다.
- 메뉴표기 모드에서는 POS_ORDER_ITEM의 메뉴명과 수량을 표시한다.

## 판매 화면
- 좌측: 메뉴분류 및 판매터치키
- 우측: 주문 상품 목록, 단가/수량/금액, 수량 증감/선택 삭제
- 우측 주문 상품 영역 상단의 '기존 주문내역 불러오기' 버튼으로 선택 테이블의 진행 중 주문을 불러온다.
- 불러온 주문은 기존 주문 항목을 기준으로 수량 변경 및 선택 삭제가 가능하고, 메뉴를 추가한 뒤 '주문 저장'을 누르면 변경 사항을 기존 주문에 반영한다.
- 기존 주문내역을 불러오지 않고 메뉴를 저장하면 기존 동작처럼 신규 메뉴만 추가 주문으로 저장한다.
- 저장 시 기존 주문의 항목 삭제/수량 변경/신규 항목 추가와 주문 합계를 하나의 DB 트랜잭션으로 처리한다. 전체 항목을 삭제하는 것은 막고 주문 취소 절차를 사용하도록 한다.
- 신규 추가 메뉴는 별도 주방 주문서로 출력한다. 기존 메뉴의 수량 변경은 주문 항목 데이터와 주방 디스플레이 조회값에 반영하며, 이미 출력된 종이 주문서에 대한 별도 취소/수정 안내지는 아직 제공하지 않는다.
- 하단: 합계, 주문 저장, 프린터 설정, 영수증 재출력, 결제
- 기존 결제/메뉴재고/레시피 원재료 차감 로직은 유지한다.

## 적용 및 확인
1. 최신 feature/okpos-sales-screen 브랜치를 내려받는다.
2. Delphi Win32 Build All을 수행한다.
3. 테이블 목록에 매장별 활성 테이블이 모두 표시되는지 확인한다.
4. 주문 전 테이블과 주문 진행 중 테이블의 색상/금액/경과시간 표시를 확인한다.
5. 메뉴표기 전환과 테이블 선택/테이블 목록 복귀를 확인한다.
6. 카테고리/메뉴 선택, 주문 저장, 추가 주문, 결제, 주방 출력 및 원재료 차감을 확인한다.
7. `database/17_table_customer_details.sql`을 적용한 뒤 방문 인원/주문자명 저장, 기존 주문 재진입 시 자동 조회, 테이블 카드 표시를 확인한다.



## 기존 주문 편집 확인
1. 진행 중 주문이 있는 테이블을 선택하고 '기존 주문내역 불러오기'를 누른다.
2. 기존 메뉴/옵션/수량/금액이 오른쪽 주문 리스트에 표시되는지 확인한다.
3. 기존 메뉴 수량을 +/−로 변경하거나 선택 삭제한다.
4. 새 메뉴를 추가하고 주문 저장 후 테이블 금액 및 주문내역이 정확히 반영되는지 확인한다.
5. 다시 기존 주문내역을 불러와 변경 내용이 DB에 저장되었는지 확인한다.
6. 기존 주문내역을 불러오지 않은 상태의 추가 주문도 기존 합계에 누적되는지 확인한다.


## 주문내역 버튼 및 주문 리스트 정렬
- 주문 리스트 상단 버튼은 기본적으로 '주문내역'으로 표시하며, 누르면 현재 선택 테이블의 진행 중 주문을 불러온다.
- 주문내역을 불러온 뒤에는 버튼 문구가 '초기화'로 바뀐다.
- '초기화'는 확인 메시지 없이 화면에 표시된 주문 리스트와 편집용 임시 상태만 비우며, 데이터베이스의 주문/주문항목은 수정하거나 삭제하지 않는다.
- 단가, 수량, 금액 열의 셀 값은 오른쪽 정렬한다.


## 결제 및 영수증 재출력
- 기존 주문내역을 불러온 후 변경하지 않은 상태라면, 주문 리스트가 화면에 표시되어 있어도 바로 결제할 수 있다.
- 불러온 주문에 메뉴 추가/삭제/수량 변경 등 저장하지 않은 변경이 있으면 주문 저장을 먼저 안내한다.
- '영수증 재출력'은 선택한 테이블의 모든 결제 완료 주문을 오래된 순서부터 각각 재출력한다.


## 레시피 원재료 재고 부족 시 결제
- 레시피 원재료 재고가 필요량보다 적더라도 POS 결제를 차단하지 않는다.
- 결제 트랜잭션에서 실제 레시피 사용량을 차감하며, 부족분은 음수 재고로 기록한다.
- 결제가 정상 커밋된 뒤 부족 원재료명, 결제 전 현재고, 필요량, 결제 후 재고를 경고 메시지로 표시한다.
- 원재료 입고는 재고관리의 원재료 구매/입고 기능으로 처리한다.


## 원재료 재고 부족 결제 및 음수 재고
- 레시피 원재료 재고가 필요량보다 적더라도 POS 결제를 차단하지 않는다.
- 실제 사용량만큼 재고를 차감하며 부족분은 음수 재고로 기록한다.
- 결제 완료 후 부족 원재료, 현재고, 필요량, 차감 후 재고를 경고한다.
- 이를 위해 DB 마이그레이션 `database/16_allow_negative_ingredient_stock.sql`을 적용해야 한다.
- 마이그레이션은 원재료 재고 및 원재료 이동 이력의 0 이상 CHECK 제약조건만 제거하며 기존 데이터는 변경하지 않는다.


## 결제 완료 후 화면 전환 및 선택 테이블 표시
- 결제가 정상 완료되면 장바구니/기존 주문 불러오기 상태를 초기화하고 테이블 카드 목록 화면으로 자동 복귀한다.
- 테이블 카드를 선택해 판매 화면에 진입하면 좌측 상단의 '테이블' 문구 오른쪽에 선택된 테이블명을 표시한다. 글꼴 크기와 굵기는 '테이블' 문구와 동일하게 유지한다.


## 테이블 고객 정보
- 판매 화면 상단에서 방문 인원(1명 이상)과 주문자명을 입력한다.
- 주문 저장 시 POS_ORDER.CUSTOMER_COUNT 및 POS_ORDER.ORDERER_NAME에 함께 저장한다.
- 기존 진행 주문을 선택하면 저장된 인원과 주문자명이 자동으로 표시된다.
- 테이블 현황 카드에는 진행 중 주문의 인원과 주문자명, 주문금액, 최초 주문시각 및 경과시간을 표시한다.
- 메뉴표기 모드에서도 고객 정보가 유지되며, 메뉴명과 수량이 함께 표시된다.
- 기존 주문은 마이그레이션 기본값으로 인원 1명이 설정되고 주문자명은 비어 있다.
- 적용 스크립트: database/17_table_customer_details.sql (16번 마이그레이션 적용 후 1회 실행)
