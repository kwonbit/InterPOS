# POS 판매 및 주문 저장

## 포함 기능
- 로그인한 매장의 사용 중인 테이블 목록 조회
- 음식 종류별 사용 중인 메뉴 조회
- 메뉴 선택 시 장바구니 추가 및 동일 메뉴 수량 자동 증가
- 장바구니 수량 증가/감소 및 항목 삭제
- 메뉴 단가와 수량을 기준으로 합계 계산
- 주문 헤더와 주문 품목을 하나의 Firebird 트랜잭션으로 저장
- 주문 품목에는 판매 시점의 메뉴명과 단가를 복사해 보관

## DB 변경
기존 POS_ORDER / POS_ORDER_ITEM 구조를 사용합니다.
`database/04_pos_sales.sql`은 주문/주문품목 ID 시퀀스를 생성하고 기존 데이터가 있을 경우 다음 ID부터 시작하도록 초기화합니다. 또한 주문 품목에 옵션 설명과 옵션 추가금액 스냅샷 필드를 추가합니다.

기존 DB에는 `database/03_master_data.sql` 적용 후 `database/04_pos_sales.sql`을 한 번 실행합니다. 이미 실행한 migration을 재실행하지 마세요.

## 사용 방법
1. 메인 화면에서 POS 판매를 선택합니다.
2. 주문할 테이블을 선택합니다.
3. 음식 종류 버튼을 선택합니다.
4. 메뉴 버튼을 눌러 장바구니에 담습니다.
5. 수량 + / 수량 - / 삭제 버튼으로 주문 내용을 조정합니다.
6. 주문 저장을 누르면 주문번호가 생성되고 POS_ORDER 및 POS_ORDER_ITEM에 저장됩니다.

## 기존 테이블 추가 주문
- 테이블 선택 시 진행 중인 주문(ORDER_STATUS='OPEN')과 현재 주문 합계를 표시합니다.
- 해당 테이블에 진행 중 주문이 있으면 새 주문 품목을 기존 POS_ORDER에 추가합니다.
- 기존 주문의 TOTAL_AMOUNT를 추가 주문 금액만큼 갱신합니다.
- 진행 중 주문이 없으면 새 주문을 생성합니다.
- 주문 헤더와 품목 추가, 합계 갱신은 하나의 Firebird 트랜잭션으로 처리합니다.

## 메뉴 옵션 선택 및 금액 반영
- 메뉴에 연결된 활성 옵션 그룹과 활성 옵션을 POS에서 조회합니다.
- 필수 선택 그룹은 최소 1개 선택해야 하며, 그룹별 MAX_SELECT 제한을 적용합니다.
- 선택한 옵션명은 주문 품목 OPTION_TEXT에 저장합니다.
- 선택한 옵션의 추가금액 합계는 OPTION_AMOUNT에 저장하고 메뉴 단가에 더해 판매 금액을 계산합니다.
- 서로 다른 옵션 조합은 장바구니에서 별도 품목으로 관리하며, 동일한 메뉴와 옵션 조합은 수량을 합산합니다.
- 메뉴관리 화면의 음식 메뉴 탭에서 '메뉴 옵션 설정'을 열어 옵션을 관리합니다.
- '옵션 그룹 등록'에서 그룹명, 필수 선택 여부(Y/N), 최대 선택 개수를 입력합니다. 최대 선택 개수 0은 제한 없음입니다.
- 그룹을 선택한 상태에서 '그룹 수정'으로 그룹명/필수 여부/최대 선택 개수를 변경하고, '그룹 삭제'로 사용 중지 처리할 수 있습니다. 삭제 처리한 그룹과 그 하위 옵션은 POS 선택 목록에서 제외됩니다.
- 그룹을 선택한 상태에서 '옵션 등록'을 눌러 옵션명과 추가 금액을 입력합니다.
- 옵션 목록에서 항목을 선택하고 '옵션 수정'으로 이름/추가 금액을 변경하거나 '옵션 삭제'로 사용 중지 처리할 수 있습니다.
- 삭제는 실제 행을 지우지 않는 논리 삭제(ACTIVE_YN='N') 방식으로 처리하여 기존 주문의 옵션명/금액 스냅샷을 보존합니다.
- 아래 메뉴 목록에서 메뉴를 선택한 뒤 '선택 메뉴에 연결'을 누르면 해당 메뉴에 옵션 그룹이 연결됩니다.
- 연결 해제가 필요하면 같은 그룹과 메뉴를 선택하고 '메뉴 연결 해제'를 누릅니다.
- 옵션 그룹/옵션과 메뉴 연결은 기존 MENU_OPTION_GROUP, MENU_OPTION, MENU_ITEM_OPTION_GROUP 테이블을 사용하며 추가 migration은 필요하지 않습니다.

## 결제 처리

- POS 판매 화면 하단의 '결제' 버튼으로 선택 테이블의 진행 중 주문(OPEN)을 결제합니다.
- 결제 수단은 현금 또는 카드이며, 현재 버전은 미결제 잔액 전액 결제를 지원합니다.
- 현금 결제는 받은 금액을 입력하며, 결제 금액보다 적으면 저장되지 않습니다. 결제 완료 후 거스름돈을 안내합니다.
- 카드 결제는 미결제 잔액을 결제 금액으로 저장합니다.
- 결제는 POS_PAYMENT 저장과 POS_ORDER 상태 변경(OPEN → PAID)을 하나의 Firebird 트랜잭션으로 처리합니다.
- 결제 완료된 주문은 진행 중 주문 조회에서 제외되어 추가 주문 및 중복 결제가 방지됩니다.
- 기존 DB에는 `database/05_pos_payment.sql`을 한 번 실행해 `GEN_POS_PAYMENT_ID` 시퀀스를 생성해야 합니다.
- 영수증 프린터 출력, 부분 결제/복합 결제, 결제 취소 및 환불은 후속 단계에서 구현합니다.
