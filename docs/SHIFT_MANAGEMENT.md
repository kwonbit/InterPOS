# 영업 개점/마감 및 현금시재 관리

## 적용 환경
- Delphi 12 Athens / VCL / FireDAC
- Firebird 5.0
- 기존 InterPOS 데이터베이스에 추가 적용

## 데이터베이스 마이그레이션
기존 DB에 `database/07_sales_closing.sql`까지 적용되어 있어야 합니다.

그 다음 `database/08_operational_foundation.sql`을 **한 번만** 실행합니다. 이미 적용한 migration은 다시 실행하지 않습니다. `01_schema.sql`은 기존 DB에서 재실행하지 않습니다.

이 migration은 주문에 작업 직원/단말 정보를 기록하고, 결제에 받은 금액/거스름돈/승인 상태를 보존하며, `POS_SHIFT`와 `POS_CASH_MOVEMENT`를 추가합니다.

## POS 단말 설정
실행 파일과 같은 폴더의 `InterPOS.ini`에서 다음 값을 확인합니다.

```ini
[POS]
StoreId=1
TerminalId=1
```

단말 정보가 아직 등록되어 있지 않으면 영업관리 화면을 처음 열 때 해당 매장에 기본 단말명 `POS 1` 형태로 자동 등록합니다. 이미 같은 단말번호가 다른 매장에 등록되어 있으면 오류를 표시합니다.

## 사용 순서
1. 직원 로그인
2. 메인 화면에서 **영업 개점 / 마감 및 현금시재** 선택
3. **영업 개점**을 누르고 실제 준비금을 입력
4. 영업 중 현금 입금/출금이 발생하면 사유와 금액을 등록
5. POS 판매는 영업 개점 이후에만 진입 가능
6. 마감 전 미결제 주문을 모두 처리
7. **영업 마감**을 누르고 실제 현금 시재를 입력
8. 예상 시재와 실제 시재 차이를 확인하고 마감 확정
9. **마감 이력**에서 과거 단말별 마감 결과 확인

## 예상 시재 계산
예상 시재는 아래 규칙으로 계산합니다.

```text
예상 시재 = 개점 준비금
         + 영업 세션 중 승인된 현금 결제액
         + 현금 입금액
         - 현금 출금액
시재 차이 = 실제 시재 - 예상 시재
```

현금 결제액은 판매 금액 기준으로 계산합니다. 고객에게 받은 금액과 거스름돈은 `POS_PAYMENT.RECEIVED_AMOUNT` 및 `CHANGE_AMOUNT`에 별도로 보존합니다.

## 마감 통제
- 해당 단말에 미결제 상태(`ORDER_STATUS='OPEN'`)인 주문이 있으면 마감할 수 없습니다.
- 마감 확정 시 세션 상태를 `CLOSED`로 변경하고 예상/실제 시재, 차액, 마감 직원 및 마감 시각을 저장합니다.
- 한 매장/단말에서 동시에 열린 영업 세션은 하나만 허용합니다.
- 마감된 세션은 다시 열지 않습니다. 다음 영업은 새 세션으로 개점합니다.

## 테스트 체크리스트
- [ ] 신규 단말 자동 등록
- [ ] 준비금 0원 및 양수 개점
- [ ] 동일 단말 중복 개점 차단
- [ ] POS 판매 진입 시 개점 여부 확인
- [ ] 현금 결제 시 예상 시재 증가
- [ ] 현금 입금 시 예상 시재 증가
- [ ] 현금 출금 시 예상 시재 감소
- [ ] 미결제 주문이 있으면 마감 차단
- [ ] 실제 시재 입력 및 차액 계산
- [ ] 마감 후 같은 단말 재개점 가능
- [ ] 마감 이력의 직원/시각/금액 표시
- [ ] 다른 단말의 매출이 현재 단말 시재에 섞이지 않는지 확인

Delphi 컴파일과 실제 Firebird migration/업무 테스트는 개발 PC에서 확인해야 합니다. 이 작업 환경에서는 Delphi 컴파일러와 사용자의 Firebird 데이터베이스에 접속할 수 없습니다.
