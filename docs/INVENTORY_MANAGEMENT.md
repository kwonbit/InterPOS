# 재고관리

## 적용 환경
- Delphi 12 Athens / VCL / FireDAC
- Firebird 5.0
- 기존 InterPOS 데이터베이스

## 데이터베이스 마이그레이션
기존 DB에 `database/08_operational_foundation.sql`까지 적용된 상태에서 `database/09_inventory_management.sql`을 한 번 실행합니다.

이미 적용한 마이그레이션은 다시 실행하지 마세요. `01_schema.sql`은 빈 DB를 처음 생성할 때만 실행합니다.

## 메뉴별 재고관리 설정
1. 점주 또는 매니저 계정으로 로그인합니다.
2. 메인 화면에서 **재고관리**를 엽니다.
3. 재고관리할 메뉴를 선택하고 **재고관리 설정**을 누릅니다.
4. 재고관리 사용 여부에 `Y`를 입력합니다.
5. 안전재고 수량을 입력합니다.

재고관리를 사용하지 않는 메뉴는 판매되어도 재고가 차감되지 않습니다. 기존 메뉴는 마이그레이션 후 기본값이 미사용(`N`)입니다.

## 재고 처리
- **입고 등록**: 구매 등으로 들어온 수량을 현재고에 더합니다.
- **출고 등록**: 폐기/샘플/기타 사유로 수량을 차감합니다. 현재고보다 큰 수량은 출고할 수 없습니다.
- **재고 실사 조정**: 실제로 확인한 재고 수량을 입력하여 시스템 현재고와 차이를 조정합니다.
- 모든 수동 변경은 변경 전/후 수량, 사유, 비고, 처리 직원, 처리 시각을 이력으로 남깁니다.

## POS 판매 자동 차감
- 주문 저장 시점에는 재고를 차감하지 않습니다.
- 결제 완료 트랜잭션 안에서 재고관리 사용 메뉴의 주문 수량을 차감합니다.
- 재고가 주문 수량보다 적으면 결제 및 재고 변경을 모두 취소하고 부족 메뉴/수량을 안내합니다.
- 결제가 성공한 경우에만 판매 차감 이력이 `POS_STOCK_MOVEMENT`에 `SALE` 사유로 저장됩니다.
- 같은 메뉴가 주문 품목에 여러 줄로 있어도 메뉴별 수량을 합산하여 한 번 차감합니다.
- 옵션 추가금액은 메뉴 재고 수량을 별도로 차감하지 않습니다.

## 재고 상태
- 현재고가 안전재고 이하이면 **재고 부족**으로 표시합니다.
- 안전재고가 0이면 자동 부족 경고는 표시하지 않습니다.
- 재고관리 미사용 메뉴는 **미관리**로 표시합니다.

## 테스트 체크리스트
- [ ] 메뉴별 재고관리 사용/미사용 설정
- [ ] 안전재고 등록 및 재고 부족 표시
- [ ] 입고 등록 후 현재고 증가
- [ ] 출고 등록 후 현재고 감소
- [ ] 현재고보다 많은 수량 출고 차단
- [ ] 실사 조정으로 현재고를 0으로 변경
- [ ] 재고 이력에 변경 전/후, 직원, 시각 기록
- [ ] 재고관리 미사용 메뉴는 판매해도 재고 미차감
- [ ] 재고관리 사용 메뉴 결제 시 재고 자동 차감
- [ ] 재고 부족 메뉴 결제 시 결제/재고 모두 롤백
- [ ] 여러 메뉴가 포함된 주문의 메뉴별 재고 차감 확인
- [ ] 결제 완료 후 매출/주방/재고 흐름이 기존대로 동작하는지 확인

Delphi 컴파일과 Firebird 5.0 실제 DB 테스트는 개발 PC에서 진행해야 합니다. 이 작업 환경에서는 사용자의 Delphi 컴파일러 및 Firebird 데이터베이스에 직접 접속할 수 없습니다.
