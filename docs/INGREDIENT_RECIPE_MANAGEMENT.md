# 원재료 및 메뉴 레시피 관리

## 개요

database/14_ingredient_recipe_management.sql을 적용하면 매장별 원재료와 메뉴 레시피를 관리할 수 있습니다.

## 데이터 구성

- POS_INGREDIENT: 원재료명, 재고 단위, 현재고, 안전재고, 이동평균 단가, 사용 여부
- POS_MENU_RECIPE: 메뉴 1개 판매에 필요한 원재료별 사용량
- POS_INGREDIENT_MOVEMENT: 원재료 입고·출고·조정 이력 저장 기반

원재료 단위는 g, kg, ml, L, 개, 봉, 팩을 기본 제공하며, 한 원재료의 재고와 레시피 사용량은 동일한 단위로 입력해야 합니다. 예를 들어 원재료 단위를 g로 등록했다면 레시피 사용량도 g 기준으로 입력합니다.

## 화면 사용

1. 점주 또는 매니저로 로그인합니다.
2. 메인 화면에서 '원재료 / 메뉴 레시피 관리'를 엽니다.
3. 왼쪽에서 원재료명, 단위, 안전재고를 등록합니다.
4. 등록된 원재료를 선택하면 이름·단위·안전재고를 수정할 수 있습니다.
5. 사용 중지할 원재료를 선택하고 '사용 중지'를 누릅니다. 데이터는 삭제하지 않고 비활성화합니다.
6. 오른쪽에서 메뉴를 선택하고 원재료와 메뉴 1개당 사용량을 등록합니다.
7. 기존 레시피를 목록에서 선택하면 원재료와 사용량을 수정할 수 있습니다. 동일 메뉴에 같은 원재료를 중복 등록할 수 없습니다.

## 현재 단계의 범위와 주의사항

원재료 구매 입고가 확정되면 현재고와 이동평균 단가가 갱신됩니다. POS 주문을 최종 결제하면 메뉴별 레시피 사용량을 주문 수량만큼 계산하여 원재료 재고를 자동 차감합니다.

## POS 결제 시 원재료 자동 차감

- 동일 주문에 여러 메뉴가 있고 같은 원재료를 공유하면 원재료별 필요량을 먼저 합산한 뒤 한 번 차감합니다.
- 원재료 현재고가 필요량보다 적으면 결제를 중단합니다. 메뉴 재고 차감, 원재료 재고 차감, 이동 이력, 결제 기록은 하나의 Firebird 트랜잭션으로 처리되므로 모두 롤백됩니다.
- 사용 중지된 원재료가 레시피에 남아 있으면 결제를 차단합니다. 해당 원재료를 다시 사용하거나 레시피를 수정해 주세요.
- 원재료 차감 이력은 POS_INGREDIENT_MOVEMENT에 OUT 유형, SALE 참조 유형 및 주문 ID로 기록합니다.
- 결제 트랜잭션에서 주문 행을 잠그고 OPEN 상태를 확인한 뒤 결제 완료로 변경하므로 결제 재시도나 동시 결제로 동일 주문이 중복 차감되지 않습니다.
- 원재료 재고 및 이동 이력의 수량 정밀도에 맞춰 POS 차감 수량은 소수점 셋째 자리까지 저장합니다.
- 레시피가 등록되지 않은 메뉴는 원재료를 차감하지 않으며 기존 메뉴 재고 기능은 그대로 적용됩니다.

## 테스트 확인 항목

1. 레시피가 등록된 메뉴를 주문하고 결제한 뒤 원재료 현재고가 레시피 사용량 × 판매 수량만큼 감소하는지 확인합니다.
2. 서로 다른 메뉴가 같은 원재료를 사용하는 주문에서 필요량이 합산되어 한 번 차감되는지 확인합니다.
3. 원재료 재고가 부족한 상태에서 결제하면 결제가 실패하고, 메뉴 재고·원재료 재고·결제 내역·재고 이동 이력이 모두 변경되지 않는지 확인합니다.
4. 사용 중지된 원재료가 레시피에 연결된 경우 결제가 차단되는지 확인합니다.
5. 레시피가 없는 메뉴는 기존처럼 결제되고 원재료 재고에는 변화가 없는지 확인합니다.
6. 동일 주문을 중복 결제할 수 없고 원재료 OUT 이력이 중복 생성되지 않는지 확인합니다.
7. 기존 메뉴 재고관리 사용 메뉴의 재고 차감 및 재고 이력이 이전과 동일하게 동작하는지 확인합니다.

기존 MENU_ITEM의 메뉴 재고 기능, 기존 구매 데이터 및 POS 판매 이력은 유지합니다. 원재료 차감은 기존 메뉴 재고 차감과 같은 결제 트랜잭션에서 처리합니다.
